--CONTAINER--
Create container -> docker run -d --name my-local-cloud -p 4566:4566 localstack/localstack:3.4.0

Create awslocal variable -> doskey awslocal=aws --endpoint-url=http://localhost:4566 $*

Check variable -> awslocal s3 ls

--S3--
Create Bucket -> curl -X PUT "http://localhost:4566/first-bucket"

Remove Bucket -> awslocal s3 rb s3://first-bucket

Upload CSV -> curl -X PUT -H "Content-Type:text/csv" --data-binary "@users.csv" "http://localhost:4566/first-bucket/users.csv"

Verify Upload -> curl -X GET "http://localhost:4566/first-bucket/users.csv" (Read Content) OR curl -X GET "http://localhost:4566/first-bucket (List bucket contents)

Security -> Access Controls [Block Public Acces, IAM policies, Bucket Policies], Encryption [At Rest, In Transit], Data Protection [Bucket Versioning, Object Lock], Monitoring [Cloudtrail, Guard Duty]

s3 Bucket Policy -> {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowPublicRead",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket-name/*",
      "Condition": {
        "IpAddress": {
          "aws:SourceIp": "192.168.1.0/24"
        }
      }
    }
  ]
}

s3 Versioning: Uploading files(overwriting), Deleting files(Delete Markers)

s3 Replication: Cross Region Replication, Same Region Replication, RTC

s3 Storage Class: Standard(Daily Active Usage), Intelligent Tiering(Unpredictable), Standard IA(Mahine mai 1-2 baar), Onezone IA(Mahine mai 1-2 baar + Non critical data), Glacier Flexible(Backup data), Glacier Deep Archive(pta nhi kb chahiye)

s3 Lifecycle: aws s3api put-bucket-lifecycle-configuration --bucket my-test-bucket --lifecycle-configuration file://lifecycle.json
->set lifecycle policy:
  {
  "Rules": [
    {
      "ID": "Automated Backup Lifecycle Policy",
      "Filter": {
        "Prefix": ""
      },
      "Status": "Enabled",
      "Transitions": [
        {
          "Days": 30,
          "StorageClass": "STANDARD_IA"
        },
        {
          "Days": 90,
          "StorageClass": "GLACIER"
        },
        {
          "Days": 180,
          "StorageClass": "DEEP_ARCHIVE"
        }
      ],
      "Expiration": {
        "Days": 365
      }
    }
  ]
}
-> Transitions Actions : Move file 
-> Expiration Actions: Delete file

s3 Event Notification: aws s3api put-bucket-notification-configuration --bucket my-test-bucket --notification-configuration file://notification.json --endpoint-url=http://localhost:4566
-> set event notification policy:
{
  "LambdaFunctionConfigurations": [
    {
      "Id": "TriggerImageProcessor",
      "LambdaFunctionArn": "arn:aws:lambda:us-east-1:000000000000:function:resize-image",
      "Events": ["s3:ObjectCreated:*"],
      "Filter": {
        "Key": {
          "FilterRules": [
            { "Name": "prefix", "Value": "uploads/" },
            { "Name": "suffix", "Value": ".png" }
          ]
        }
      }
    }
  ]
}
-> Target (Supported Destination): Lambda, SQS, SNS, EventBridge

s3 Performance: Baseline Performance(Prefix depend speed), Multipart upload, Byte-range fetches, Cloudfront caches, Transfer Acceleration

s3 Encryption: Encryption in Transit (aws:SecureTransport:False), Encryption at Rest(SSE, CSE)(Data key, Master key)

s3 Access Point: aws s3control put-access-point-policy --account-id 123456789012 --name finance-ap --policy file://finance-policy.json

s3 Tables: Apache Iceberg, Glue/Athena
-> Table Bucket: aws s3tables create-table-bucket --name my-table-bucket --region us-east-1

s3 Storage Lens: Dashboard

Amazon EBS: Elastic Block Store, Virtual Hard Drive for EC2
-> Data Persistent(Data doesn't disappear when server stops)
-> OS Boot Drives(Store Operating System)
-> High Performance for DB
-> Snapshot & Backup (Took point in time EBS snapshot that are saved to s3)
-> Elasticity (20gb - 200gb, HDD - SSD without turning off server) 

Amazon EFS: Elastic File System, NFS

Amazon Backup: Centralized Backup
-> Multiservice                                 -> Disaster recovery(Cross region copy)
-> Ransome Protection(Vault Lock)

--DYNAMODB--

Amazon DynamoDB: NoSQL DB, Key-Value Data, JSON structure
->Read/Write Capacity Modes (RRU=upto 4kb/WRU=upto 1kb)
-> On Demand Mode(Automatic scaling, Billing depend on RRU/GRU)
-> Provisioned Mode(We defined read/write unit)

DynamoDB Indexes: Create Secondary Copy
-> Local Secondary Index(LSI): Partition Key same but New Sort Key
-> Global Secondary Index(GSI): Both Partition and Sort key new

DynamoDB PartiQL: SQL support for CRUD

DynamoDB Accelerator(DAX): In-memory Cache

DynamoDB Streams: Change occur trigger notification/event
-> keys_only(modified item's primary key)                   -> old_image(old item)
-> new_image(modified item)                                 -> new_and_old_image(new and old item)

DynamoDB TTL: Delete expired data
-> Epoc Timestamp(in Seconds)                       -> Automatic Deletion(within 48 hrs)
-> Background Scanner

DynamoDB with S3 Patterns: Combination power of s3 and DynamoDB
-> Large Item/Offboarding Bypass(400 kb limit)            -> Direct Bulk Import/Export(import from s3 and export to s3)
-> Cold Storage Data Archiving(TTL+s3)

DynamoDB Security: Security for Data
-> Authentication(who access)                   -> Encryption(Data Protection)
-> Authorization(what access)                   -> Network Protection(VPC Private AWS Internet)

--REDSHIFT--

Amazon Redshift: Columnar Storage, MPP Architecture(Single Leader node, Multiple Compute Nodes), Cluster of Servers, OLAP not OLTP

Redshift Spectrum: Use SQL on S3, Glue Data Catalog, Smart File Format (Apache Paraquet)

Redshift Distribution Styles: Leader node, Compute Nodes
-> Even Distribution: Equally distributed
-> Key Distribution: cust101 complete data in node1
-> All Distribution: Copy of data for each node
-> Auto Distribution: All and Even according to data size

WLM: Redshift Workload Management, Traffic Controller, Divide query in queues
-> Memory Allocation: We decide, size needed for which type of query
-> Auto WLM: Redshift use ML/AI, Allocate memory ont the basis of priority
-> SQA: Short Query Acceleration: Automatically execute short queries first

VACUUM: Redshift's Maintainance/Cleanup Tool
-> Reclaim Disk Space: Deleted marked rows permanently
-> Re Sort Rows: Unsorted rows get sorted by SORT KEY

RA3 Nodes: Feature to make achitect Decoupled(Storage and compute different)

--MIGRATION AND TRANSFER--

Application Discovery Service: Analysis report of servers
-> Collect data in two types: Agentless Discovery(VMs), Agent based Discovery(Agent Software)
-> Utilise Collected data: Dependency Mapping(Visual map of connection), Cost Estimation(Costing on the basis of Performance metrics)

Data Migration Service: Operational DB to AWS Cloud
-> Zero Downtime: Full load - Ongoing Replication - Cutover
-> Migration Types: Homogenous Migration(PostgreSQL to Aurora PostgreSQL, same engine), Hetrogenous Migration(Oracle to Aurora PostgreSQL, different engine)

AWS Snowball: Physical Hard Drive which got delivered then upload and then sent to AWS Center
-> Members of Snowball Family: AWS Snowcome(8TB), AWS Snowball Edge(80TB to 210TB), AWS Snowmobile(100PB)

AWS Data Exchange: Third party Data, like Kaggle

--COMPUTE--

EC2: Elastic Compute Cloud, Big data computing, Distributed Computing, Specailized Hardware(NVMes, RAM), High speed inter node networking, Dynamic Elasticity
-> Families of EC2: Storage optimized(D-series & I-series)[NVMes/SSDs/HDDs], Memory optimized(R-series & X-series)[Heavy RAM], Compute Optimized(C-series)[High CPU], Accelerated Computing(P-series & G-series)[AI/Deep learning models]

AWS Graviton: AWS own ARM-based processor

AWS Lambda: Function block, run code snippets in the cloud, 15 min max runtime
-> Zero Server Management                   -> Automatic Scaling
-> Pay per request(per ms)                  -> Event Driven Execution

AWS SAM: CLI tool and utility, template.yaml, create serverless services

AWS Batch: Same as lambda, more than 15 min runtime, query in queue, not instant processed
