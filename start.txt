--S3--
Create Bucket -> curl -X PUT "http://localhost:4566/first-bucket"

Remove Bucket -> awslocal s3 rb s3://first-bucket

Upload CSV -> curl -X PUT -H "Content-Type:text/csv" --data-binary "@users.csv" "http://localhost:4566/first-bucket/users.csv"

Verify Upload -> curl -X GET "http://localhost:4566/first-bucket/users.csv" (Read Content) OR curl -X GET "http://localhost:4566/first-bucket (List bucket contents)

Security -> Access Controls [Block Public Acces, IAM policies, Bucket Policies], Encryption [At Rest, In Transit], Data Protection [Bucket Versioning, Object Lock], Monitoring [Cloudtrail, Guard Duty]

s3 Bucket Policy -> {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowPublicRead",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket-name/*",
      "Condition": {
        "IpAddress": {
          "aws:SourceIp": "192.168.1.0/24"
        }
      }
    }
  ]
}

s3 Versioning: Uploading files(overwriting), Deleting files(Delete Markers)

s3 Replication: Cross Region Replication, Same Region Replication, RTC

s3 Storage Class: Standard(Daily Active Usage), Intelligent Tiering(Unpredictable), Standard IA(Mahine mai 1-2 baar), Onezone IA(Mahine mai 1-2 baar + Non critical data), Glacier Flexible(Backup data), Glacier Deep Archive(pta nhi kb chahiye)

s3 Lifecycle: aws s3api put-bucket-lifecycle-configuration --bucket my-test-bucket --lifecycle-configuration file://lifecycle.json
->set lifecycle policy:
  {
  "Rules": [
    {
      "ID": "Automated Backup Lifecycle Policy",
      "Filter": {
        "Prefix": ""
      },
      "Status": "Enabled",
      "Transitions": [
        {
          "Days": 30,
          "StorageClass": "STANDARD_IA"
        },
        {
          "Days": 90,
          "StorageClass": "GLACIER"
        },
        {
          "Days": 180,
          "StorageClass": "DEEP_ARCHIVE"
        }
      ],
      "Expiration": {
        "Days": 365
      }
    }
  ]
}
-> Transitions Actions : Move file 
-> Expiration Actions: Delete file

s3 Event Notification: aws s3api put-bucket-notification-configuration --bucket my-test-bucket --notification-configuration file://notification.json --endpoint-url=http://localhost:4566
-> set event notification policy:

--APPLICATION INTEGRATIONS--

SQS: Simple Queue Service, Message queuing service, do ya ushsey jayda app ke beech me async communication krwata hai
-> Decoupling: Seperate consumer and produceer direct link and filt itself in between which allow to consumer to process data as per its speed so app not get crashed.
-> Rate limiting & Buffer: Work like a breaker so help to prevent data loss
-> Poisioning Message Handling: Dead Letter Queue, Those msgs which crashed application send them to error handling queue to fix

SNS: Simple Notification Service, Messaging service hai, Notification dena jinn jinn ney subscribe kr rakkha hoga
-> Publisher: Sender, Jo SNS ko message bheta hai
-> Topic: Logical access point, grouping zone hota hai jaha message aatey hai 
-> Subscriber: Jo topic se judey huai hai jaise hi topic mai naye message aata hai SNS sb subscriber ko instantly push kr deta hai

SNS SQS Fan out: Services bs 1 message SNS topic pr publish karegi SNS ushey 3 alg alg SQS Queue mai fan out (copy) kr dega. 

AWS Step Function: Visual workflow Orchestrator(State Machine) service, Alag alag aws services ko aapas mai connect krke ek multi step automated besiness worflow(pipline) bnana.
-> State Machine: Amazon State Language, Workflow step function ka ek JSON based structure me define hota hai jishey state mahine kehte hai.
-> Types of state: Task State(Lambda run), Choice State(If/Else), Parallel State, Map State(array per loop), Wait State(Timeout Interval), Fail/success state.
-> Built in Error Handling & Retries: if step fail, automatically retry or send to specific catch/fallback block me bhej deta hai

Amazon Appflow: Fully managed integration service (SaaS Connector), SaaS app ko AWS services ke beech mai data securly move or sync krna bina koi custom code aur API integration likhey

Amazon EventBridge: Serverless event bus, central hub jo saarey events ko ek jagah recieve krta hai rule apply and then send to services to work on that data.
-> Event source(Kahan se aa raha hai)                         -> Rules(Filtering & Routing logic)
-> Event Bus(Router)                                          -> Targets(kahan bhejna hai)

Amazon MWAA: Managed workflow for Apache Airflow, managed service which allow to run open source Apache Airflow and provide environment, infra, and security.

--NETWORK--

VPC: GBN key physical layer-2/layer-3 hardware key upar chlta hua software defined Virtual Network (SDN) which give isolate layer-3 IP subnetting environment deta hai 

Subnets: VPC key under ka IP address mgmt system, VPC 10.0.0.0/16 (total 65,536 IPs), subnet 10.0.1.0/24 (total 256 IPs), Each subnet has atatched route table which decide IP get Internet access or not.
-> Public Subnets: 0.0.0.0/0 (Internet Gateways) Ishme jo bhi EC2 bnaya ushko ek public IP milege aur woh direct Internet se connect ho sakta hai
-> Private Subnets: Internet ka direct route blocked (sirf internal VPC traffic allowed), Servers ko sirf private IP (10.0.2.x) milti hai, Outside interne t se koi ishko directly ping/access block

Internet Gateways: Component of VPC which connect VPC to public internet, AWS fully managed software defined service layer hai

NAT Gateway: To connect internet with Private IPs

NACL: Network Access Control LIst, Subnet level virtual FW, Control traffic of in and out.

Security Groups: Instance level virtual FW, Resources mai inbound and outbount control

VPC Flow logs: VPC key under IP traffic (NW packets) ka metadata record capture krta hai

VPC peering: Networking Connection which allow routing between tow VPCs via private IP addresses, Network to network

AWS PrivateLink: It's technology used by VPC endpoints, that enables you to privately connect your VPC to aws services and does not leave AWS network, Service to servbice

VPC endpoints: AWS feature which allow to connect privately with any AWS services or third party services without going in public internet

DNS: Domain Name System, DNS Recursive Resolver (Router/ISP) -> Root name server (.) -> TLD name Server (.com) -> Authorative Name Server (example=10.21.93.4)

Amazon Route 53: AWS ki highly scalable DNS web service hai, Route 53 because work on TCP/UDP port 53, Route user traffic to internet application.
-> Domain Name Registration: Domain Khareedna
-> DNS Mgmt/Traffic Routing: Domain name ko IP address se connect krna.
-> Health Checking: When primary serverdown then traffic automatically redirect to backup server
